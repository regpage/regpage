# Logger (PHP 7.4+)

Простой файловый журнал с уровнями `INFO`, `DEBUG`, `ERROR` и `FATAL`. Для каждого дня создаётся отдельный файл `дд.мм.гггг.log`; каждая запись заканчивается разделителем `=========================`.

## Использование

Подключите класс и создайте экземпляр:

```php
require_once __DIR__ . '/Logger.php';

$logger = new Logger();
$logger->info('Приложение запущено');
$logger->debug('Параметры запроса', ['user_id' => 42]);
$logger->error('Не удалось загрузить данные');
$logger->fatal('Критическая ошибка');
```

По умолчанию журнал находится в `Logger/logs` — рядом с `Logger.php`. Путь привязан к файлу класса через `__DIR__`, а не к текущей рабочей папке процесса, поэтому вызовы из cron, веб-страниц и AJAX используют один каталог.

Можно задать собственный абсолютный или относительный путь:

```php
$logger = new Logger(__DIR__ . '/var/logs');
```

Каталог создаётся автоматически вместе с родительскими каталогами. Запись дополняет файл, а `LOCK_EX` предотвращает перемешивание одновременных записей.

## Запуск тестов

Из корня проекта выполните:

```sh
php Logger/tests/run.php
```

Скрипт выводит результат каждой проверки и завершается с кодом `0`, если всё прошло, или `1` при ошибках. Тестовые файлы создаются во временном системном каталоге и удаляются после выполнения.

### Визуальный тест с сохранением журнала

Основной запуск `php Logger/tests/run.php` также создаёт сохраняемый визуальный журнал: по одной записи каждого уровня в `Logger/tests/visual-logs/дд.мм.гггг.log`. Тест выводит путь к файлу и не удаляет каталог после завершения. Отдельно тот же визуальный тест можно запустить командой `php Logger/tests/visual.php`. После проверки журнал можно удалить вручную:

```sh
rm -rf Logger/tests/visual-logs
```

На Windows удалите каталог `Logger\\tests\\visual-logs` через проводник или команду `rmdir /s /q Logger\\tests\\visual-logs`.

## Возможные трудности записи

- **Недостаточно прав.** Пользователь, запускающий PHP (веб-сервер или cron), должен иметь право создавать каталог и записывать файлы. Проверьте владельца и права каталога; права должны быть назначены нужному пользователю/группе. Не используйте `0777` как универсальное исправление.
- **Разные пользователи запуска.** Веб-сервер и cron могут работать от разных пользователей. Если они пишут в один каталог, настройте общую группу и права доступа либо укажите общий каталог с корректным владельцем.
- **Нет места на диске / файловая система только для чтения.** `file_put_contents()` не сможет записать файл; класс выбросит `RuntimeException`.
- **Некорректный путь.** Убедитесь, что родительский каталог доступен для создания, а путь не указывает на уже существующий файл.
- **Смена дня и часовой пояс.** Имя файла и время записи формируются часовым поясом PHP (`date.timezone` или `date_default_timezone_set()`). Настройте его до записи, если нужен конкретный часовой пояс.
- **Секретные данные.** Не передавайте пароли, токены и другие чувствительные данные в сообщениях или `context`; лог-файлы содержат их в открытом виде.

Ошибки создания каталога или записи приводят к `RuntimeException`; некорректный уровень — к `InvalidArgumentException`. Контекст, который нельзя сериализовать в JSON, тоже приводит к `InvalidArgumentException`. Например, используйте `try/catch` вокруг записи, если ошибка журнала не должна прерывать основную операцию. Уровень `FATAL` только помечает запись и не перехватывает необработанные исключения или ошибки PHP.
